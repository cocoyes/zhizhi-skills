# 设计与接入依据

核对日期：2026-11-05。依据当前本地源码，不假定其他版本完全一致。

## 现状与范围

本项目开始时只有《知枝生活Skills开发指引.md》，尚无代码、依赖或 Git 元数据。相邻 runtime 示例为 `examples/14-skills/skills/greeting/SKILL.md`，契约为 `docs/runtime-skills.md`，加载与排序位于 `skill/catalog.go`、`skill/search.go`，执行器位于根目录 `skill.go`。相邻 zhizhi-go 的 `api/agent/skills` 仅有 README，`api/agent/internal/agent/skills/provider.go` 已有 provider 接入，配置支持 `Skills.Roots` 和空 `AllowedTools`。

首版交付 Skill 包；本次根据用户新要求接入已有只读搜索与地图能力：不新增业务 API/RPC、数据表、画像、持久状态、脚本业务工具、前端或外部服务，不改变现有服务职责与接口契约。

## 方案选择

1. **自包含 SKILL.md（本次采用）**：适合 10 个综合生活领域；只有 `name`、`description` frontmatter 和领域方法。无依赖，加载后可直接使用；每个 Skill 保留一份共同输出约束，避免加载不到仓库根级规则。
2. **SKILL.md 加按需 references**：若以后有足够大的稳定专业材料，可以通过已有 `skill.read_resource` 读取。目前领域方法可直接容纳，拆分只会增加工具调用与遗漏风险，暂不采用。
3. **计算脚本、档案、新联网服务**：需要新增授权、执行环境或数据维护，不在本次新增；已有搜索和地图服务按需复用。复杂计算宁可说明缺项与计算口径，不编结果；将来确有需求再单独评估。

以上目录与组织是本次实施选择，不新增 metadata 字段或 runtime 机制。10 个目录对应 10 个综合领域；示例覆盖细分需求，但不额外注册子 Skill。

## 真实执行机制与权限

1. `skill.Catalog.LoadRoot(ctx, root)` 支持单个 Skill 或包含多个 Skill 的父目录；见到 SKILL.md 后停止向下注册，重复名称/重叠根等会拒绝。不要同时注册本项目根目录和其 skills 子目录。
2. catalog 索引名称、描述和指纹，`Metadata()` 不会自动注入模型上下文。
3. `skills.search` 只根据名称和描述搜索，中文使用相邻双字匹配，默认返回 5 个候选，最多 10 个；不是语义分类器。描述必须含自然表达，否定词也可能被匹配；中英混排可能产生偶然的英文名称匹配。
4. `skills.invoke` 使用搜索返回的 selection_id、候选名称与 task。加载正文后在受限内部模型循环中执行，不能递归调用其他 Skill。
5. 子执行只得到显式 task，不会自动获得完整主聊天历史。宿主应在 task 内传递本次目标、已确认人数/预算/禁忌、用户明确偏好和相关既有结果；只传必要信息，不复制无关敏感历史。
6. 空 `AllowedTools` 不授予业务工具；本次授权 `intelligent_search`、`discover_map_tools`、`call_map_tool`。地图发现直接调用已配置高德 MCP 并缓存工具列表，不由主 Agent 预查。高德不再进入自动模型选择目录，其他 MCP 保持原有机制。已有 `skill.read_resource` 是有界只读资源接口，本包无需调用。frontmatter 自称 allowed-tools 或正文要求工具不能授予权限。
7. 子执行的文本还会作为工具结果返回给主 Agent。主 Agent 最终回复也应保留 Markdown 协议，不能把外层 `status/text/skill_name` 等 JSON 包络直接展示。Skill 本身无法强制控制主模型的再次改写。

更新后重新索引可能改变指纹；进行中的调用受原有 selection、continuation 与 drift 校验约束，遵循 runtime 的现有恢复流程，不手工规避。

## 路由与上下文传递建议

主 Agent 应先判断用户是否需要专门方法，普通寒暄、代码开发、无关闲聊可以不搜索。需要时用用户核心目标与领域词检索，候选只是供模型选择，不能取第一名直接执行。多个诉求先解决主要目的；不足以判断且影响结果时澄清，避免同时加载多个领域。别把整段长对话当检索词来碰关键词。

举例：

- “想减脂，但今晚只问外卖怎么搭配”以饮食为主。
- “朋友借钱，我想学怎么拒绝”以关系沟通为主；“借了多少、怎么AA”以财务为主。
- “工作要学英语，想练自我介绍”以学习为主；“写给主管的延期话术”以职场为主。
- “忙完想玩接龙”以休闲为主，不能因为提到工作就启动职业分析。

文字游戏尤其要传当前规则、已用词/当前词、轮次和用户最新回答，否则无状态子执行可能从第一轮重新开始。长计划修订同样需要上一版关键内容。这是接入方传递 task 的建议，不表示本次已修改宿主自动传递逻辑。

## 内容质量标准

每个 Skill 均包含：用途/排除、自然语言理解、少量关键追问、领域处理方法、风险边界、输出与一个实际例子、独立 Markdown 协议。复杂计划考虑预算/时间/精力、保底动作、中断恢复与调整条件；短问不强行套模板。用事实与假设区分替代虚构精确性，用自主选择替代羞辱或操控。

Markdown 约束属于产品要求：用户请求网页、附件或原始结构化结果时仍以聊天内 Markdown 提供同一任务的可用文本。脚本/测试使用 JSONL 是开发数据格式，不是 Skill 给终端用户的交付格式。

## 已知限制

- 精确名称搜索和候选召回通过，不代表主模型会正确选择或执行。
- 按需使用已授权搜索与地图；工具不可用、查询失败或数据未覆盖时，只给草案和待核实项。实际结果仍可能过时，不保证价格、政策、库存或可订状态。
- 不做医疗诊断、治疗、投资保证、法律裁决与高风险维修。
- 无持久跟踪、自动提醒、预订或外部动作；跨轮信息取决于宿主传入的 task。
- Prompt 是行为约束，不是安全沙箱或输出格式强制器。生产验收仍需真实模型端到端跑案例；自动格式检查也不能证明语义、安全、数学与可执行性。

## 2026-11-05 工具能力修订

原始指引的离线范围已由用户后续明确要求调整。Skill 自己决定发现与调用地图，不依赖主 Agent 预查。`discover_map_tools` 返回实际名称/描述/参数Schema；`call_map_tool` 校验方法白名单与Schema并转发。先地点搜索取坐标、已有坐标复用、必要时补地理编码，之后路线；歧义地点澄清，不猜坐标或用户位置。具体接口见相邻 zhizhi-go 的 `docs/agent-map-skill-tools.md`。本包与宿主共同保留最终Markdown输出要求，来源链接可作为证据附在文内。

## 输出语言

根据用户最新要求，移除默认简体中文及计算结论必须使用中文的指令，不新增语言检测、解析或选择规则，由模型根据对话自行决定。原始开发指引保留为历史输入，输出语言以此修订为准。
